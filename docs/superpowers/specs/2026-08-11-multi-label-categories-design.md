# 多标签分类 + 两栏衍生词 设计

日期：2026-08-11
项目：kartu-kosakata（印尼语单词卡，纯前端单文件）
前置：`2026-08-07-root-card-redesign-design.md`（词根卡 / 词组卡重构，已完成，词库 312 张）

## 背景

上一轮把词库重构成词根卡 + 固定词组卡，词库现有 312 张（词根 233 / 词组 79）。用起来暴露两个问题：

**分类不好用。** 现有 14 个分类是从旧词库继承来的，混了场景（高频/教会/工作/生活）、词性（形容词）、主题（地形/身体/学习）、语体（口语/正式）、功能（语法/辨音/动作/词缀）四种维度，互相不平行。而且一张卡只能有一个分类，`bumi` 既是名词又是教会词，只能二选一。

**衍生词露得太少。** 每张词根卡最多 2 个衍生词，111 张已经放满。当初按重要度筛掉的那些记在 `syn` 里，等于降级成了小字。卡片背面现在是单栏，纵向排 2 条衍生词就占满了——版面本身是限制因素。

## 目标

1. 分类改成**多标签**，用一套互相平行的标签，一张卡可带多个。
2. 衍生词上限从 2 提到 4，卡片背面改**两栏**排布容纳它们。
3. 去掉词根/词组的类型筛选（`t` 字段保留，背面模板仍需要它）。

## 非目标

- 不动卡片的字段结构（除 `c` 与 `der` 上限外）。
- 不做间隔重复。掌握状态仍是二元。
- 不重新划分词根/词组的归属——那是上一轮settled的判断。

## 分类体系

十个标签，固定顺序（筛选行按此顺序渲染）：

**名词 · 动词 · 形容词 · 虚词 · 高频 · 工作 · 教会 · 生活 · 辨音 · 其他**

三组性质不同：

- **词性组**（名词/动词/形容词/虚词）—— 这个词是什么。每张卡恰好一个。
- **场景组**（高频/工作/教会/生活）—— 在哪儿会用到。零个或多个。
- **辨音** —— 易混音组的专门练习集（`berat` / `barat` / `baret`）。跨在词性之上，单独保留。
- **其他** —— 词性组和场景组都安不上时的兜底。

一张卡典型带两个标签：一个词性 + 一个场景。`bumi` = `["名词","教会"]`。

### 词性标签怎么定

**词根卡**从现有 `pos` 机械映射：

| `pos` | 分类标签 |
|---|---|
| `动词根` | 动词 |
| `名词` | 名词 |
| `形容词` | 形容词 |
| `副词` / `连词` / `介词` / `数词` / `代词` / `量词` / `词缀` | 虚词 |
| `A·B` 复合（`副词·连词`、`名词·形容词`） | 按第一个成分定；两个成分都是实词时可给两个标签 |

**词组卡**没有 `pos`，按词组**整体**的词性判：

- `air terjun` 瀑布 → 名词
- `menyangkal diri` 舍己 → 动词
- `berat hati` 不情愿 → 形容词
- `oleh karena itu` 因此 → 虚词

这样筛「名词」时，`bukit` 和 `air terjun` 会一起出来——这正是想要的。

### 场景标签怎么定

`高频` / `工作` / `教会` / `生活` 四个，从旧分类直接沿用的有 228 张。旧分类里没有对应的 83 张（口语 19 / 语法 20 / 动作 12 / 地形 11 / 形容词 9 / 身体 5 / 学习 4 / 正式 3）逐张判：

- `口语` 的词多半是高频虚词 → `虚词` + `高频`
- `语法` 同上
- `地形`（bukit / lereng / jurang）→ `名词`，场景多为 `教会`（登山宝训、山坡）或 `生活`
- `身体`（badan / lemas）→ `名词`/`形容词` + `生活`
- `学习`（ajar / kosakata）→ 视词而定 + `高频`
- `动作` → 对应词性 + 场景
- `正式` → 对应词性，场景按实际用处
- 旧 `形容词` 分类 → 词性标签 `形容词`，场景另判

判断标准：**这个词我会在什么时候用到？** 判不出来就不给场景标签，只留词性标签——这是允许的，不必强行凑。

### 兜底规则

词性组和场景组都安不上的，给 `其他`。`其他` 与其他标签互斥——一张卡有了任何别的标签，就不该再有 `其他`。

## 数据模型改动

`c` 从字符串变字符串数组：

```js
// 之前
{t:"root",w:"bumi",pos:"名词",p:"bu-mi 布-米",zh:"地、大地、地球",c:"教会", …}

// 之后
{t:"root",w:"bumi",pos:"名词",p:"bu-mi 布-米",zh:"地、大地、地球",c:["名词","教会"], …}
```

`der` 上限从 2 改为 4。其余字段不变。

### 校验规则改动（`tools/check-data.mjs`）

- `c` 必须是非空字符串数组，每个值都在十个标签的封闭列表里，数组内不重复。
- `其他` 不得与其他标签共存。
- `der` 长度上限 2 → 4。
- 其余规则不变。`lintDeck` 的例句检查不变。

## 卡片背面两栏

衍生词区改两栏网格，左右各一列，最多两行（4 条）。**辨析和例句仍占整行**——它们是连续文字，切栏会难读。

```
┌──────────────────────────────┐
│ 词性  形容词                  │
├───────────────┬──────────────┤
│ keberatan     │ memberatkan  │
│ 异议、反对     │ 使加重        │
│ mengajukan…   │ syarat yang… │
├───────────────┼──────────────┤
│ berkeberatan  │ pemberatan   │
├───────────────┴──────────────┤
│ 辨析  ⚠️ berat / barat / baret│
├──────────────────────────────┤
│ Bebanmu berat? Datanglah…    │
└──────────────────────────────┘
```

窄视口（手机竖屏）下两栏会挤，改为单栏纵向排——用 CSS 媒体查询或 `grid-template-columns: repeat(auto-fit, minmax(…))` 自适应，不写死两栏。

衍生词条目内部仍是三行：词形（加粗）/ 中文 / 用例。词组卡的背面（直译 / 提示 / 例句）不动，它没有衍生词。

卡片正面的分类标签 `tagF`/`tagB` 现在显示单个 `d.c`；改成显示数组的前两个，用 `·` 连接。

## 筛选改动

删掉整个类型筛选行：`#types` 容器、`types()`、`inType()`、`TYPE_LABEL`、`let type`，以及 `render()` 空状态里的 `scope` 拼接和初始化调用里的 `types()`。

分类筛选改成按标签命中：

```js
function inCat(d){ return cat === "全部" || d.c.includes(cat); }
```

分类 chip 的列表改成固定的十个（按上面的顺序），不再从 `DATA` 动态推——顺序是设计的一部分，且空分类也该显示出来（计数为 0 时仍可点，与上一轮的取舍一致）。

上一轮为「类型 × 分类」空组合加的提示（「这个组合下没有卡片」）保留——单分类为空时同样用得上。

## 词库迁移

312 张全部重打 `c` 标签，233 张词根卡另过一遍看能否补衍生词。

**衍生词补充规则**：现有 `syn` 里记着「落选：X」的，把常用的提上来填进 `der`（上限 4）。仍排不进的，在 `syn` 里保留一句提及；不常见的直接略过，不必凑满 4 个。补充时仍守上一轮的判据——优先偏离词根本义最远的、不同词缀家族的。

## 测试

- 校验脚本自身的单测扩充：`c` 数组合法/非法、`其他` 互斥、`der` 上限 4。
- 全量校验：312 张零错误、零例句提示。
- 全库对账：每张卡的 `c` 都非空且合法；十个标签各自的卡数打印出来复核；`其他` 的数量应当很小（是兜底不是垃圾桶）。
- 浏览器：两栏在桌面与手机视口都不裁切、不横向滚动；单分类筛选正确；空分类提示正确；翻面、打乱、掌握、清空、跨设备同步全部回归。
