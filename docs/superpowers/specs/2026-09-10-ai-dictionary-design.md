# AI 词典 + 词库缓存 + 查询时间线 设计

日期：2026-09-10
项目：kartu-kosakata（印尼语单词卡，纯前端单文件）
前置：`2026-08-11-multi-label-categories-design.md`（多标签分类，已完成，词库 312 张）
来源：`D:\02Barnabas\工具\katakosa\gem设定.txt`（Gemini gem「终极元提示词 V3.8」）

## 背景

现在查一个印尼语生词，流程是：打开 Gemini，进那个 gem，输入词，读它吐出来的 Markdown 报告。报告读完就没了。同一个词过两周再忘，重查一遍，重新烧一次 token，也看不出自己到底在哪些词上反复栽跟头。

单词卡 App 这边，312 张卡全是手写进 `DATA` 数组的。加一张词得改 `index.html`、跑校验、提交。查词和背词是两个完全断开的动作。

把 gem 搬进 App，让查过的词自动沉淀成个人词库，是这一轮要做的事。

## 目标

1. App 内直接查词，输出与 gem 同等深度的报告。
2. 查过的词（含衍生词）落库，再查直接读库，不重复调 AI。
3. 时间线视图：按日期倒序看查过什么。
4. 频次视图：按查询次数分桶（1 次 / 2-5 次 / 5 次以上）筛词库。
5. 词典条目可一键转成学习卡，进入现有牌组。

## 非目标

- 不新建应用，不拆文件。全部嫁接进现有 `index.html`，单文件、无构建、GitHub Pages 直接跑的性质不变。
- 不动现有 312 张手写卡的数据结构和卡片视图。
- 不做间隔重复。掌握状态仍是二元。
- 不做多用户。同步码就是身份，个人用。

## 关键决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| AI 接入 | Google AI Studio 免费 key，浏览器直连 `generativelanguage.googleapis.com` | 该域允许跨域，纯静态页可直接 fetch，零后端零成本。免费档额度个人用绰绰有余 |
| key 存放 | 跟进度一起存 `progress/{code}` | 填一次手机电脑都能用。代价是 key 明文在 Firestore，知道同步码的人能读到；免费档 key，风险可接受 |
| 词库与牌组关系 | 独立词典库，可一键转卡片 | 手写卡是精挑细选的，AI 条目不冲淡它 |
| 报告存储 | 结构化 JSON | 衍生词可单独索引、可转卡片、排版可改。Markdown 原文不存 |
| 衍生词计数 | 全算词根头上 | 库小，一个词根一条记录。具体搜的是哪个形式记在 `via` 字段里，不丢信息 |
| 日历形态 | 倒序时间线列表 | 手机上好滑 |

## 数据模型

全部挂在现有同步码文档下，不新开顶层集合。

```
progress/{code}                      knownV2: string[]        （现有）
                                     apiKey: string           （新增）
progress/{code}/lexicon/{rootSlug}   词典条目，一个词根一个文档
progress/{code}/cards/{cardSlug}     一键转出来的学习卡
```

### 词典条目 `lexicon/{rootSlug}`

`rootSlug` = 词根小写、空格转连字符。歧义词按语言分开存，slug 加后缀：`kata`（印尼语）、`kata--en`（英语）。

```js
{
  root: "ajar",              // 词根 / 基本形式
  lang: "id",                // "id" | "en"
  query: "mengajar",         // 首次查询时输入的原词
  ipa: "ˈa.dʒar",            // 词根发音
  core: "教导",              // 核心解释（对应模板「核心解释」）
  rootBlock: {               // 对应模板 A 部分
    ipa: "ˈa.dʒar",
    zh: "教导、传授",
    phrases: [ {t:"belajar mengajar", zh:"教与学"}, … ],   // 恰好 3 条
    examples: [ {t:"…", zh:"…"}, … ]                       // 恰好 2 条
  },
  ders: [                    // 对应模板 B 部分，不限数量
    { w:"mengajar", ipa:"…", zh:"教、授课",
      phrase:{t:"…", zh:"…"}, example:{t:"…", zh:"…"} },
    …
  ],
  derSlugs: ["mengajar","ajaran","pelajar","pelajaran"],  // 检索索引，含词根本身
  count: 3,                                               // = hits.length
  hits: [ {at:"2026-09-10T07:12:00Z", via:"mengajar", ai:true},
          {at:"2026-09-14T02:03:00Z", via:null, ai:false} ],
  model: "gemini-flash-latest",
  createdAt: "2026-09-10T07:12:00Z"
}
```

`hits[].via` 是本次实际输入的词；直接搜词根时为 `null`。`hits[].ai` 表示这次是否真的调了 AI（首次为 `true`，之后命中缓存为 `false`）。时间线和频次都从 `hits` 推导，不另存日志集合。

### 学习卡 `cards/{cardSlug}`

字段与 `DATA` 里的词根卡完全一致，多一个 `src:"dict"` 标记来源：

```js
{ t:"root", w, pos, p, zh, c:[…], der:[{w,zh,ex}×最多4], syn, ex, src:"dict" }
```

牌组 = `DATA` 拼上 `cards` 集合。`cardId()` 逻辑不变，来源不同的同名卡视为同一张（后写的覆盖）。

## 查词流程

```
输入词 → 归一化（trim、小写、压缩空格）
      → 查本地索引：遍历已加载的 lexicon，命中 root 或 derSlugs 任一项
      ├─ 命中 → 追加 hit {ai:false} → 渲染缓存条目，滚到命中的那个衍生词
      └─ 未命中 → 调 Gemini
                ├─ 返回 ambiguous → 弹《语言歧义提示》三选一 → 带 lang 参数再调一次
                └─ 返回条目 → 写入 lexicon（hit 的 ai:true）→ 渲染
```

歧义处理保留 gem 的行为。AI 首轮可能返回：

```js
{ ambiguous: true,
  brief: { en: "英文核心含义简述", id: "印尼文核心含义简述" } }
```

界面出「英文 / 印尼文 / 两者都要」三个按钮。选「两者都要」时发两次请求，存两个文档。

## 提示词改造

gem 的 Markdown 模板改写成 JSON schema 约束的结构化输出（Gemini 的 `responseMimeType: "application/json"` + `responseSchema`）。排版交给前端，AI 只出内容。

原提示词里这些规则原样保留：

- 角色是印尼语 / 英语 / 中文三语词典助手，权威度对标 dict.com。
- 准确识别输入是印尼语还是英语；两种语言都有明确常用且不同的词义时，走歧义分支。
- 印尼语词找出 Kata Dasar；英语词找出 base form / root。
- `ders` 第一项必须是词根本身的形式，除非词根不能独立成词，此时从第一个有效衍生词开始。
- 衍生词列全，常见的和不常见的都要，不限数量。
- 词根块恰好 3 个短语、2 个例句；每个衍生词块恰好 1 个短语、1 个例句。
- 所有中文标签（「衍生词」「例句」「含义」）不进内容字段——那些现在是前端的静态文案。

发音字段统一用 IPA。原模板允许「IPA 或标准发音」，两可会让缓存里的数据不齐，这里收紧成只要 IPA。

## 界面

顶部导航加一行三个页签：**卡片 · 词典 · 日历**。默认停在卡片，与现在的行为一致。

**卡片页**：不动。牌组多了转过来的卡而已。

**词典页**：

- 顶部搜索框 + 查询按钮。回车即查。
- 结果区按模板结构渲染：标题词、语言/词根/发音一行、核心解释、词根块（3 短语 2 例句）、衍生词列表。命中缓存时在标题旁标一个「库中」小标记和查询次数。
- 结果区底部一个「转成学习卡」按钮，弹分类多选（沿用现有十个标签），写入 `cards`。已转过的显示「已在牌组」。
- 结果区下方是词库列表，四个筛选按钮：全部 / 1 次 / 2-5 次 / 5 次以上。点条目展开为完整报告。

**日历页**：

倒序时间线，按日期分组。每组标日期 + 当天词数，下面铺词。调了 AI 的实心，命中缓存的描边。词条显示实际搜的形式，命中衍生词时写成 `mengajar → ajar`。点词跳到词典页对应条目。

**设置**：现有同步弹窗里加一栏 API key 输入框，附一行说明和 aistudio.google.com/apikey 链接。key 存在时只显示尾四位。

## 错误处理

| 情况 | 行为 |
|---|---|
| 没连同步码 | 词典页可用，数据只存 localStorage；提示连同步码才能跨设备 |
| 没填 key，点查询 | 结果区显示引导文案，一个按钮直接打开设置 |
| key 无效（401/403） | 「密钥无效或已过期」，引导去设置 |
| 超额（429） | 「今日免费额度用完了，明天再试」，缓存照常可查 |
| 离线 / 网络失败 | 「连不上，词库里的词仍然可以查」 |
| AI 返回不合 schema | 重试一次；仍失败则报错，不写库 |

任何 AI 失败都不写 `lexicon`，也不记 hit。缓存查询全程不依赖网络。

## 测试

纯函数抽出来放在 `tools/` 下，用 `node --test` 跑：

- `normalizeQuery` — trim、小写、压缩连续空格。
- `findInLexicon` — 命中词根、命中衍生词、未命中、大小写与空格差异。
- `bucketByCount` — 1 / 2-5 / 5 以上的边界（1、2、5、6）。
- `entryToCard` — 词典 JSON 转卡片，衍生词截到 4 个、字段映射、分类透传。
- `groupHitsByDate` — 跨天分组、同日合并、倒序。

Gemini 调用用假响应打桩，不打真网络。`tools/check-data.mjs` 扩一条：校验词典条目 JSON 的必填字段与数量约束（3 短语 / 2 例句 / 每个衍生词 1+1）。
